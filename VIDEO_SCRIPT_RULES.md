## The Purpose of This Document

A Loom screen recording of a dashboard posted directly to TikTok will not perform. Nigerian business owners scrolling TikTok are not looking for a product demo — they stop for something that speaks directly to their problem in the first two seconds.

This file turns a project into a structured TikTok video script. The script tells Adedamola exactly what to record, in what order, and what text overlay to place on each scene. The output is designed for assembly in any basic video editing tool — CapCut, VN, InShot, or similar.

The target is 25-35 seconds total. That is the optimal length for this content type on TikTok for a Nigerian business audience.

---

## Before You Begin

Read the following before generating anything:

1. The project's Knowledge Document if it exists — this is the primary source of business context and the before/after story
2. The project's portfolio fields — `overview`, `problem`, `results`
3. The brand voice rules — found in the brand persona file in this repository
4. The anti-AI writing rules — found in the ANTI_AI_WRITING file in this repository

The video script must be grounded in what is actually in the project. Do not invent scenarios or outcomes that are not supported by the project documentation.

## The Video Formula

Every video follows this exact structure. Do not deviate from it.

```
SCENE 1 — Hook (2-3 seconds)
SCENE 2 — Problem (4-6 seconds)
SCENE 3 — Transition (1-2 seconds)
SCENE 4 — Solution Walkthrough (15-20 seconds)
SCENE 5 — Result (3-4 seconds)
SCENE 6 — CTA (2-3 seconds)
```

Total: 27-38 seconds

---

## Scene-by-Scene Rules

### Scene 1 — Hook

**Purpose:** Stop the scroll in 2 seconds. The hook is the single most important part of the video. If it fails, nothing else matters.

**Format:** Full-screen text overlay on a solid or blurred background. No screen recording yet.

**Rules:**
- Maximum 8 words
- Must name a specific Nigerian business type or operation — not "businesses" but "Lagos distributors" or "WhatsApp resellers" or "service businesses in Lagos"
- Must describe the pain, not the solution
- Never start with "I built" or "Check out" or "Introducing"
- Never use forbidden words — game-changer, revolutionary, seamless, etc.
- Must create enough tension that a Nigerian business owner feels seen immediately

**Hook formula options — use the one that fits the project:**

Option A — The Cost Hook: Name what the manual process is costing.
> "Lagos businesses lose [X] hours a week to manual invoicing"

Option B — The Chaos Hook: Name the specific operational chaos.
> "Managing 80 WhatsApp orders a day with no system"

Option C — The Before Hook: Describe the before state as a statement of fact.
> "This business tracked every order in a WhatsApp group"

Generate three hook options. Mark the recommended one.

---

### Scene 2 — Problem

**Purpose:** Show the before state. Make the problem feel real and recognisable.

**Format:** 2-3 text overlay cards shown in sequence, each for 1.5-2 seconds. No screen recording yet. Each card is one sentence.

**Rules:**
- Describe the specific manual process — WhatsApp threads, Excel files, paper records, phone calls
- Use specific numbers where the Knowledge Document has them — `[ADD METRIC]` where it does not
- Write in plain language a business owner would use themselves
- Do not mention the solution yet
- Each card must be under 12 words

**Generate 3 text overlay cards in sequence.**

---

### Scene 3 — Transition

**Purpose:** The pivot from problem to solution. Creates anticipation.

**Format:** Single full-screen text overlay, 1-2 seconds.

**Rules:**
- Maximum 5 words
- Creates a clear pivot — the viewer knows something is about to change
- Never use "But wait" or "Here's the thing" or "Plot twist"

**Examples:**
- "So I built this."
- "One system fixed it."
- "This changed everything." ← only acceptable use of this phrase given its brevity and context

Generate two transition options. Mark the recommended one.

---

### Scene 4 — Solution Walkthrough

**Purpose:** Show the system working. This is where the Loom recording is used.

**Format:** Screen recording clips with text overlay captions on each clip.

**This is the most detailed section of the script.** Generate a shot list — a specific sequence of screens to record from the Loom, each with its text overlay caption.

**Shot list rules:**
- Maximum 6 shots — each 2-4 seconds long
- Start with the most visually impressive screen — the main dashboard, the automation flow, or the results view
- Each shot must show one specific thing the system does — not a general overview
- Text overlay per shot must be under 10 words and describe what the viewer is seeing
- Show the automation in action where possible — a reminder firing, an invoice generating, an order being tracked automatically
- Never show a loading screen or an empty state
- If the project has a WhatsApp integration, include a shot of it — this is the highest-impact screen for a Nigerian business audience
- If the project has a payment integration (Paystack, Flutterwave), include a shot of it
- End the walkthrough on the most satisfying screen — the one that shows the complete, working, automated state

**Shot list format:**

```
SHOT [number]:
Screen: [Exact description of what screen to navigate to and record]
Duration: [2-4 seconds]
Text overlay: [Under 10 words — what this shot proves]
```

---

### Scene 5 — Result

**Purpose:** State the outcome. Numbers land harder than adjectives.

**Format:** 1-2 text overlay cards, each 1.5-2 seconds. No screen recording.

**Rules:**
- Use a specific number if one exists in the Knowledge Document — `[ADD METRIC]` if not
- Write the result as a fact, not a claim — "Zero missed orders" not "significantly reduced order errors"
- Maximum 10 words per card
- Never use vague outcome language — "improved efficiency", "better workflow", "transformed operations"

**Examples of good result cards:**
- "Zero missed orders since launch"
- "[ADD METRIC] hours saved per week"
- "Payments tracked automatically. No spreadsheet."
- "Runs in the background. Owner does nothing."

Generate 2 result card options. Mark the recommended one.

---

### Scene 6 — CTA

**Purpose:** Tell the viewer exactly what to do next.

**Format:** Single text overlay, 2-3 seconds. Can include the demoladevop.com URL.

**Rules:**
- Maximum 8 words
- Must give one specific action — not two
- Must include demoladevop.com or a reference to the portfolio
- Never use "Like and follow for more" or "Drop a comment below" or "DM me"
- The CTA must connect to the project specifically — not a generic "see my work"

**Examples:**
- "Full case study at demoladevop.com"
- "See how it works — demoladevop.com"
- "Built for Nigerian businesses — demoladevop.com"

Generate two CTA options. Mark the recommended one.

## TikTok Posting Notes

Generate these alongside the script so Adedamola has everything needed to post immediately after editing:

**Caption:** A single sentence under 100 characters. Must state the specific business problem. Must include `demoladevop.com`. Never use generic developer hashtags like #coding or #webdev.

**Hashtags:** Maximum 5. Must be specific to the audience:
- `#NigerianBusiness` always
- `#BusinessAutomation` always
- One industry-specific tag based on the project — `#LagosBusiness`, `#SMENigeria`, `#WhatsAppBusiness`, etc.
- One problem-specific tag — `#InvoiceAutomation`, `#OrderManagement`, `#BookingSystem`, etc.
- One optional developer tag only if the project has a strong technical angle — `#BuildInPublic`, `#NextJS`, `#TechInNigeria`

**Best posting time for Nigerian TikTok audience:**
Saturday evening 7-9pm WAT or Sunday afternoon 3-6pm WAT. These are the highest-engagement windows for Nigerian business content on TikTok.
